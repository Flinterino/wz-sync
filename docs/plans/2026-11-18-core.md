# L2 Core implementation plan

Owner approved .NET 10 LTS on 18 November 2026. This stage is a library, not a launcher. Separate from approved L3 design PR.

## Global constraints

- A hard-coded managed policy in the client; the downloaded manifest can only narrow it, never widen it.
- Re-validate every path case-insensitively, reserve `.wzsync/`, refuse symlinks and Windows junctions. Reject traversal, absolute paths, ADS, Windows reserved names and ambiguous names. Only top-level mods and exact approved configs.
- Only HTTPS to github.com, objects.githubusercontent.com, release-assets.githubusercontent.com, mediafilez.forgecdn.net, edge.forgecdn.net, cdn.modrinth.com. Validate every redirect hop before following it; automatic redirects disabled. Initial GitHub assets restricted to Flinterino/wz-sync releases. Re-check SHA256 AND byte size.
- A .sha256 sidecar proves integrity only, not publisher identity. README must say this.
- Planning is read-only. Explicit Apply is the caller approval boundary. All payloads staged in selected profile .wzsync/tmp and verified before any managed mutation. Manual missing/mismatched rows block the whole apply; matching local bytes can KEEP.
- Backup originals under .wzsync/backup before replacement/removal. Durable journal, failure rollback and interrupted-operation recovery. Restore previews all inverse actions, verifies backup bytes and refuses modified current files; backs up current versions first. No silent data loss.
- No downloaded code execution, telemetry, admin, services, registry, startup entries, game/server access or unmanaged file synchronization. Local logs contain relative file paths and phases, no secrets/URLs with signed query/personal profile paths.
- Public repo, no private export/logs or personal data. BCL-only production dependencies. Test fixtures use temporary directories. Tests must pass in GitHub Actions on Linux and Windows. Never merge own PR.

## Task 1: policy, models, parser and planner

Create .NET10 library and xUnit tests, solution, global.json and ignore build output. Implement immutable validated manifest models matching schema1 (pack/full-lite, version, minecraft1.21.1, loader neoforge-21.1.265, managed[], files[] path/sha256/size/source/url/page/availability/reason). Reject unknown fields, duplicate keys and case-insensitive path collisions, malformed hashes/sizes, policy widening and file outside declared scope. Manual/download semantics enforced. Hard-code exact policy from approved L1 list. Safe profile resolver checks existing ancestors/root/leaf for reparse points including dangling links and junctions, also internal state. Planner produces immutable ADD/UPDATE/REMOVE/KEEP plus current SHA/size snapshots, no writes, no unmanaged reads. Test adversarial paths, symlinks, policy narrowing, case collisions and manual gating. Record stable API for later tasks. Build and tests before review.

## Task 2: verified download

Implement initial-source URL policy, every-hop redirect validation, bounded streaming SHA256 and size verification and staged-file recheck. Production owns handler with automatic redirects disabled; test-only injection uses internal API. Test allowed GitHub signed asset redirects, evil intermediate/host suffix/HTTP/userinfo/port, redirect limit and wrong/short/oversized bytes. No real network in unit tests. Review before next task.

## Task 3: apply, backup, restore and recovery

Implement explicit apply of approved immutable plan, exclusive state lock, manual gate, stage all files and recheck current snapshots, journal and backup original bytes before installing verified payloads. Guard every path including internal paths. Restore as inverse reviewed plan, with stale-current and backup-integrity refusal. Failure rollback and interrupted-journal recovery must preserve unknown concurrent edits and fail closed rather than claim Ready. Local relative-path phase logs. Test full add/update/remove/keep roundtrip, all-download-first failure, changed plan, malicious journal, interruption and rollback, concurrent lock, unmanaged preservation and restore refusal after edits.

## Task 4: integration, CI and final review

README API usage, policy and trust limits, no GUI/production-ready claim, .NET10 SDK exact pin. GitHub Actions Windows+Linux build/tests with official action commits pinned. Full local Release tests, privacy/whitespace diff check and independent whole-branch security review. Fix findings, repeat covering tests, open one PR and wait for Actions. Update central task/handoff/memory/LOG close metadata only after concrete results.
